Go agent SDK / v0.7.0 / one run call

Agents that are simple to write.
Secure by default.

kritrim is a small Go SDK for AI agents. One model, one tool constructor, one run call — every built-in capability goes through one broker, and the whole agent can run inside a sandbox that reaches the outside world only through the host.

One way to do it

One Config, one NewTool, one Run / Stream. No module registry, no presets, no second constructor.

Secure by default

Shell and HTTP refuse to exist without allowlists. Secrets never reach the model. Every redirect is re-validated.

Durable by design

A run can pause for a person, persist in the session, and resume in another process — including inside a sealed box.

Ships with the hard parts

A2A, MCP, evals, OTel, triggers, memory, skills, graph and swarm — as small packages, not a platform.

Quickstart

From an empty folder to an agent with a typed tool, a stream and a saved conversation.

Hello

package main

import (
	"context"
	"fmt"
	"log"

	"github.com/ganeshdipdumbare/kritrim"
)

func main() {
	a, err := kritrim.New(kritrim.Config{
		Model:        kritrim.Anthropic("claude-sonnet-5-5"),
		Instructions: "You are concise.",
	})
	if err != nil {
		log.Fatal(err)
	}
	defer a.Close()

	res, err := a.Run(context.Background(), "Say hello in five words.")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Text)
}

No key? Use kritrim.Mock(kritrim.Turn{Text: "hello"}) and the same code runs offline.

A typed tool

func weather(ctx context.Context, in struct {
	City string `json:"city" desc:"city name"`
}) (string, error) {
	return "18C and light rain in " + in.City, nil
}

a, _ := kritrim.New(kritrim.Config{
	Model: kritrim.Mock(
		kritrim.TurnTool("weather", map[string]any{"city": "Lisbon"}),
		kritrim.Turn{Text: "It is raining in Lisbon."},
	),
	Tools: []kritrim.Tool{kritrim.NewTool("weather", "Get the weather", weather)},
})
defer a.Close()

res, _ := a.Run(ctx, "What is the weather in Lisbon?")

The schema comes from the Go type. A string result goes to the model as is; anything else is JSON.

Stream

for e, err := range a.Stream(ctx, "Plan a trip") {
	if err != nil { break }

Concepts

The words used across these docs, in one place.

TermWhat it is
AgentWhat kritrim.New(Config) returns: a model, tools, hooks, a session store and optional sandbox.
RunOne Run or Stream call. It ends with a Result: text, steps, usage, stop reason and interrupts.
StepOne model call inside a run, plus the tool calls it asked for.
ToolA typed Go function with a name, a derived JSON Schema and a result.
SessionA conversation stored under an id (Thread("id")), including paused approvals. Memory, file or SQL.
HookA callback around the run, a model call or a tool call. Hooks can observe and shape; built-in security runs first.
ApprovalA risky tool asks Config.Approve. The decision can be synchronous or a durable pause.
InterruptA paused approval with a stable id. Resume with Decisions.
SandboxWhere shell and file tools run: Docker, Local (development) or SSH.
SealedThe whole agent runs in a sandbox. The host only brokers model calls, secrets, tools, audit and approvals.
BrokerThe one path built-in tools use for network, processes and files. It enforces allowlists, SSRF checks and redaction.

Tools

The schema is derived from the Go type; the callable is not exported, so NewTool is the only way to define one.

type SearchIn struct {
	Query string `json:"query" desc:"what to look for"`
	Limit int    `json:"limit,omitempty" desc:"max results"`
	Sort  string `json:"sort,omitempty" enum:"relevance,date"`
}

search := kritrim.NewTool("search_tickets", "Search support tickets",
	func(ctx context.Context, in SearchIn) ([]Ticket, error) {
		return db.Search(ctx, in.Query, in.Limit)
	})

a, _ := kritrim.New(kritrim.Config{Model: model, Tools: []kritrim.Tool{search}})
  • Tags: json, desc and enum. omitempty or a pointer makes a field optional.
  • Results: a string goes to the model as is; anything else is JSON.
  • Errors: a returned error becomes an error tool result, so the model can recover.
  • Risky: kritrim.Risky(tool) asks Config.Approve before the call.
  • Validated: the model's arguments are checked against the schema before the tool runs, for typed, raw and MCP tools alike: types, required fields, enum/const, unknown fields, string length and pattern, numeric ranges, array sizes, anyOf/oneOf/allOf/not and local $ref. A schema keyword that cannot be enforced (a remote $ref, if/then, patternProperties…) makes the call fail instead of passing unchecked.

Parallel calls

One model step can ask for several tools. ToolConcurrency runs them together; risky tools always stay sequential so approvals keep their order.

a, _ := kritrim.New(kritrim.Config{
	Model:           model,
	Tools:           tools,
	ToolConcurrency: 4,
})

Direct calls

out, err := a.CallTool(ctx, "search_tickets", map[string]any{"query": "refund"})

Streaming

Stream returns an iter.Seq2. Breaking out early cancels the run and cleans up.

	if err != nil { break }
	if e.Type == "text" { fmt.Print(e.Text) }
}

Sessions and state

A session is a conversation plus a small key-value state. It is version-checked, so two writers cannot silently overwrite each other.

a, _ := kritrim.New(kritrim.Config{
	Model:   model,
	Session: kritrim.FileSessions(".agent/sessions"),
	// or kritrim.MemorySessions(), kritrim.SQLSessions(db, cfg)
})
defer a.Close()

a.Run(ctx, "My name is Ada.", kritrim.Thread("user-42"))
res, _ := a.Run(ctx, "What is my name?", kritrim.Thread("user-42"))

State

Tools and hooks read and write per-session state. It is saved with the session and never sent to the model.

kritrim.StateFrom(ctx).Set("seen", true)
v := kritrim.StateFrom(ctx).Get("seen")

Fork, cancel, idempotency

a.Fork(ctx, "user-42", "user-42-experiment") // snapshot, including paused state
a.Cancel("run-7")                            // stop a run started with kritrim.RunID("run-7")
res, _ := a.Run(ctx, "charge", kritrim.Idempotency("order-1234"))
Conflict

If another process saved the session first, Save returns ErrSessionConflict. Reload and retry; the run never silently loses a turn.

Approvals

Synchronous for a CLI; durable for a server that answers hours later.

In-process

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Tools: []kritrim.Tool{kritrim.Risky(refund)},
	Approve: func(ctx context.Context, req kritrim.Approval) (kritrim.Decision, error) {
		fmt.Println(req.Message)
		return kritrim.Approve(), nil // or Reject, Edit, Respond
	},
})

Durable pause

Return Pause(). The run saves the pending step with the session and returns interrupts.

Approve: func(ctx context.Context, req kritrim.Approval) (kritrim.Decision, error) {
	return kritrim.Pause(), nil
},

res, _ := a.Run(ctx, "Refund A-17", kritrim.Thread("ticket-981"))
// res.Stop == "interrupt"; res.Interrupts[0].ID

// Later, in another process with the same session store:
res, _ = a.Run(ctx, "", kritrim.Thread("ticket-981"),
	kritrim.Decisions(map[string]kritrim.Decision{
		res.Interrupts[0].ID: kritrim.Approve(),
	}))
  • The model is not called again on resume; only the remaining tools run.
  • A second resume gets ErrSessionConflict, so a tool runs once.
  • A paused thread refuses a new prompt until the interrupts are answered.
  • This works in sealed mode: pending state crosses the RPC boundary and survives a box restart.

Structured output

Ask for a Go type instead of text. One repair round, then ErrOutput.

type Trip struct {
	City    string   `json:"city"`
	Packing []string `json:"packing" desc:"things to pack"`
	Budget  int      `json:"budget_eur,omitempty"`
}

var trip Trip
_, err := a.Run(ctx, "Plan Lisbon", kritrim.Output(&trip))
if err != nil { /* kritrim.ErrOutput */ }
fmt.Println(trip.City, trip.Packing)

OpenAI and Gemini use native JSON schema; Anthropic and Bedrock get a forced tool; OpenAI-compatible providers can use JSON mode. The schema is derived from the same tags as a tool.

Security

Enabling a built-in capability is the grant. There is no second policy file to drift from the code.

Default deny

HTTP and Shell refuse to be constructed without an allowlist. Files is read-only unless Write: true.

SSRF and rebinding

Exact allowlisted hosts may be private; wildcard hosts must be public, checked at dial time on the IP actually connected to, so DNS rebinding cannot reach an internal address. Every redirect is re-validated.

Secrets

secret://NAME resolves at use and is redacted from output, events and audit. A request that carries a secret never follows a redirect to another host. Sealed boxes get random placeholders only.

No inherited credentials

Shell commands, MCP stdio servers and local boxes start with a minimal environment (PATH, HOME, locale, temp dir). Your API keys never reach them; pass extras with ShellConfig.Env or MCPConfig.Env.

Symlink-safe files

File tools open their root with os.Root: a symlink inside the root cannot read or write outside it.

Validated arguments

Tool arguments are checked against the tool schema before the call, so a model cannot pass types, values or fields the tool did not declare.

Audit

One hash-chained JSON line per model, tool and approval. With AuditKey the chain is HMAC-signed and a signed head detects truncation.

Limits

a, _ := kritrim.New(kritrim.Config{
	Model:  model,
	Limits: kritrim.Limits{Steps: 20, ToolCalls: 50, Tokens: 200_000},
	Audit:  kritrim.AuditFile(".agent/audit.jsonl", kritrim.AuditKey(auditKey)),
	Secrets: map[string]string{"GITHUB_TOKEN": os.Getenv("GITHUB_TOKEN")},
})

Defaults: 20 steps, 100 tool calls and kritrim.DefaultTokenLimit (1,000,000) tokens per run. Set Tokens: -1 to remove the token cap. The token budget is checked before every model call, including the structured-output repair call: a call whose estimated input does not fit is refused, and the output limit is capped to what remains. In sealed mode the host enforces the run's Limits.Tokens as well as Sealed.MaxTokens.

Redaction and policy

deny, _ := guard.Deny(`(?i)ignore all previous`, "prompt injection")
a, _ := kritrim.New(kritrim.Config{
	Model: model,
	// Guards first, so tracing sees redacted values.
	Hooks: kritrim.Chain(deny, guard.PII("email", "credit_card"), trace.OTel(otelCfg)),
})

kritrim.Chain combines any number of hook sets. They run in the order given; a Before hook that errors or denies stops the chain.

Trust boundary

The broker governs built-in tools. Your own Go tools are code you compiled into the binary. Put untrusted work in a sandbox.

Sandboxes

Run shell and file tools in Docker, on a remote host over SSH, or locally for development.

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Tools: []kritrim.Tool{
		kritrim.Shell(kritrim.ShellConfig{Allow: []string{"go", "git"}}),
		kritrim.Files(kritrim.FilesConfig{Root: "/workspace"}),
	},
	Sandbox: kritrim.Docker(kritrim.DockerConfig{Image: "golang:1.27"}),
})

Hardened containers

Containers kritrim creates drop every Linux capability, set no-new-privileges, have no network, and are capped at 2 GB of memory, 2 CPUs and 512 processes. Tighten or relax per sandbox:

kritrim.Docker(kritrim.DockerConfig{
	Image:     "golang:1.27",
	User:      "1000:1000", // recommended: not root
	ReadOnly:  true,        // read-only root, writable /tmp
	Memory:    "1g",        // "none" removes the cap
	CPUs:      "1",
	PidsLimit: 256,         // -1 removes the cap
	CapAdd:    nil,         // re-add capabilities only if needed
})

An attached container (Container:) keeps the settings it was started with.

Attach or stream

// Attach to a container that already exists; Close does not remove it.
box := kritrim.Docker(kritrim.DockerConfig{Container: "agent-workspace"})

// Stream output while a command runs (Docker, Local, SSH).
m, _ := box.Open(ctx, kritrim.OpenConfig{})
sm := m.(kritrim.StreamingMachine)
sm.ExecStream(ctx, req, func(stdout, stderr string) { fmt.Print(stdout) })

SSH

import "github.com/ganeshdipdumbare/kritrim/sandbox/ssh"

box, err := ssh.New(ssh.Config{
	Host:         "ubuntu@10.0.1.5",
	WorkingDir:   "/home/ubuntu/workspace",
	IdentityFile: "~/.ssh/agent_key",
})

Host-key checking is enforced by default; extra SSH options are filtered to block directives that run local commands.

Third-party providers

Implement Sandbox, Machine and Process. Docker, Local and SSH are in the repository; every adapter must pass sandbox/sandboxtest.

The sealed agent

The whole agent runs inside the sandbox. The host only brokers. No API key, secret value or host file enters the box.

cfg := kritrim.Config{
	Model: kritrim.Anthropic("claude-sonnet-5-5"),
	Tools: []kritrim.Tool{kritrim.Shell(kritrim.ShellConfig{Allow: []string{"ls"}})},
	Sealed: &kritrim.Sealed{
		Sandbox:   kritrim.Docker(kritrim.DockerConfig{Image: "debian:bookworm-slim"}),
		Binary:    "./box", // GOOS=linux build
		Egress:    []string{"api.github.com"},
		Secrets:   map[string][]string{"GITHUB_TOKEN": {"api.github.com"}},
		MaxTokens: 200_000,
		Bridged:   []string{"crm_lookup"},
	},
}

if kritrim.InBox() {
	log.Fatal(kritrim.ServeBox(ctx, os.Stdin, os.Stdout, cfg))
}
a, err := kritrim.New(cfg)

Build the box

go run ./cmd/kritrim box build -o box .
# or: GOOS=linux GOARCH=amd64 go build -o box .

What crosses the boundary

The box needsThe host does
a model callchecks the token budget before the call, injects the key, calls the provider one call at a time, streams tokens back
a secret://returns a random placeholder, substitutes it only for allowed hosts, never follows a cross-host redirect with it, and redacts responses
a bridged toolruns it on the host; a risky one runs only for a call the host approved, once, with exactly the approved arguments
egressallowlist and SSRF checks on the host
an approvalasks Config.Approve on the host with a host-written message and persists the pause
an audit entrywrites it marked source: "box" with the host's identity

The box is treated as untrusted. User, roles, thread and run id come from the run the host started, never from the box. Every host capability call holds a lease on that run: when the run ends, in-flight calls are canceled and waited for, and new ones are refused.

Local is not isolation

kritrim.Local() exists for development and requires AllowUnsafeLocal: true. Use Docker or a cloud sandbox for a real boundary.

MCP

Connect stdio and Streamable HTTP servers. Tools are namespaced and go through the same broker and approval rules.

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	MCP: []kritrim.MCPConfig{
		{Name: "github", Command: "npx", Args: []string{"-y", "@modelcontextprotocol/server-github"}},
		{Name: "docs", URL: "https://mcp.example.com/mcp",
			Headers: map[string]string{"Authorization": "Bearer secret://MCP_TOKEN"}},
	},
})
  • Tools are named server__tool.
  • Each server has a timeout, an HTTP host allowlist and an optional Risky flag.
  • stdio servers do not inherit your environment; pass what they need in Env. HTTP servers never get a redirect off their host.
  • In sealed mode the host connects and bridges the tools into the box automatically.

A2A

Serve an agent over the Agent-to-Agent protocol and call remote agents with the same result type.

Server

srv, _ := a2a.NewServer(a2a.ServerConfig{
	Card:  a2a.Card{Name: "Triage", Description: "Routes support tickets"},
	Auth:  a2a.Bearer(os.Getenv("A2A_TOKEN")),
	Agent: func(contextID string) (*kritrim.Agent, error) { return buildAgent(contextID), nil },
	Tasks: a2a.MemoryTasks(), // or a2a.SQLTasks(db, cfg)
	PushAllowPrivate: false,
})
http.ListenAndServe(":9000", srv)

Client

c, _ := a2a.NewClient(a2a.ClientConfig{
	Endpoint: "https://triage.internal",
	Headers:  map[string]string{"Authorization": "Bearer secret://A2A_TOKEN"},
	// OAuth client credentials:
	TokenURL: "https://auth.example.com/token", ClientID: "id", ClientSecret: "secret",
	// Push every task to a webhook:
	PushURL: "https://app.example.com/a2a/events", PushToken: "shared",
})
res, _ := c.Run(ctx, "ticket 42")
tool := c.AsTool("triage", "Routes a ticket")

What is implemented

  • Agent card, message/send, message/stream, tasks/get, tasks/cancel.
  • Per-context agents with an LRU, text and data parts, and interrupt → input-required → resume.
  • Push notifications with a token, and tasks/pushNotificationConfig/{set,get,list,delete}. Push URLs must be public http(s) (checked at set time and at dial time), redirects are not followed, and header values are sent as given: secret:// is never resolved on the server.
  • Bearer auth (constant-time; an empty token is refused) and OAuth client credentials.
  • Per-caller isolation: with a2a.Tokens(map[token]principal) (or any Auth that implements Principal), each task, context, conversation and push config belongs to the caller that created it. Other callers get "task not found". With a single Bearer token, all callers share one principal.
  • The client only follows redirects on the same allowed host, so its credentials stay where you sent them.

Multi-agent

Start with an agent as a tool; reach for a graph or swarm when the path matters.

Agents as tools

expert, _ := kritrim.New(kritrim.Config{Model: model, Instructions: "You are a Lisbon expert."})
main, _ := kritrim.New(kritrim.Config{
	Model: model,
	Tools: []kritrim.Tool{expert.AsTool("lisbon_expert", "Answers Lisbon questions")},
})

Graph

g := multiagent.NewGraph().Start("triage").
	Node("triage", triageNode).
	Node("billing", billingNode).
	Edge("triage", "billing", func(s *multiagent.State) bool { return s.Get("intent") == "billing" })

res, _ := g.Run(ctx, "invoice question")

Swarm

s, _ := multiagent.NewSwarm(
	multiagent.Member{Name: "researcher", Description: "finds facts", Agent: researcher},
	multiagent.Member{Name: "writer", Description: "writes", Agent: writer},
)
res, _ := s.Run(ctx, "draft the launch post")

Members get handoff_to_<name> tools. Workflows are plain Go; there is no extra primitive.

Triggers

Run an agent on a schedule or from a signed webhook.

sched, _ := trigger.NewScheduler(agent,
	trigger.Schedule{Every: time.Hour, Thread: "daily", Prompt: "summarize yesterday"})
sched.Start(ctx)
defer sched.Close()

hook, _ := trigger.Webhook(trigger.WebhookConfig{
	Agent:  agent,
	Secret: "secret://HOOK_SECRET",
})
http.Handle("/hook", hook)

// Sender side:
ts := time.Now()
req.Header.Set(trigger.TimestampHeader, strconv.FormatInt(ts.Unix(), 10))
req.Header.Set(trigger.IdempotencyHeader, "evt-123")
req.Header.Set(trigger.SignatureHeader, trigger.Sign(secret, ts, "evt-123", body))

The HMAC-SHA256 signature covers a versioned, length-prefixed encoding of the timestamp, the idempotency key and the body. Requests outside Tolerance (default 5 minutes) are refused, so a captured request cannot be replayed later or under a new key. Each delivery runs once: duplicates, including concurrent ones, get the first result, and a delivery without a key is identified by its signature. Reusing a key for a different body returns 409. Deliveries are remembered for DedupeTTL; when MaxEntries is full of unexpired ones the webhook answers 503 with Retry-After rather than forgetting any. Errors are logged, not returned. A schedule skips a tick when its previous run is still going.

Evals

Cases, evaluators, detectors, a cache and a report you can gate CI on.

report, _ := evals.Experiment{
	Cases: []evals.Case{
		{Name: "capital", Input: "Capital of France?", Expected: "Paris"},
	},
	Evaluators: []evals.Evaluator{
		evals.Contains(),
		evals.ToolCalls(evals.ToolCallConfig{Require: []string{"lookup"}}),
		evals.LLMJudge(evals.JudgeConfig{Model: judge, Rubric: "1.0 if correct"}),
	},
	Concurrency: 4,
	Detect:      true,
	Cache:       evals.DirCache(".agent/evals"),
}.Run(ctx, func(ctx context.Context, c evals.Case) (*kritrim.Result, error) {
	return agent.Run(ctx, c.Input, kritrim.Thread(c.Name))
})
fmt.Print(report.Summary())

// plugin.Inject adds context; plugin.Steer adds a just-in-time user message.

Observability

Audit is built in. Traces, metrics and logs are one hook away.

Audit

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Audit: kritrim.AuditFile(".agent/audit.jsonl", kritrim.AuditKey(key)),
})
// later
if err := kritrim.VerifyAudit(".agent/audit.jsonl", kritrim.AuditKey(key)); err != nil { ... }

With AuditKey (32+ random bytes from a KMS or secret store, not on the log's host) every entry is chained with HMAC-SHA256 and audit.jsonl.head holds a signed record of the last entry. Someone who can write the file but lacks the key cannot rewrite or truncate it without VerifyAudit failing. Without a key the plain SHA-256 chain only detects accidental corruption. Ship the head to external storage to detect a rollback of both files.

Before its first append, a sink verifies the existing log with its own key and refuses to extend a log that fails: one that was truncated, written unkeyed or with another key, or that lost its head. An empty key is an error, never "no signing". After a failed write the sink re-reads and re-verifies the file before the next one.

Traces, metrics and logs

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Hooks: trace.OTel(trace.OTLPConfig{
		Endpoint: "http://localhost:4318",
		Service:  "support-agent",
	}),
})

trace.OTel sends OTLP/HTTP traces, metrics and logs. trace.OTLP is traces only; trace.JSON(w) writes one line per event.
