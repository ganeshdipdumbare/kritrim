The secure Go toolkit for building production agents.

Sealed mode

One boundary, brokered by the host

The agent loop, its tools and its files run in the sandbox. Keys, secrets, egress, approvals and the token budget stay on the host.

No API key in the boxToken budget on the hostAudit and approvals on the host
Principles

Small surface, safe defaults

/one-way

One Config, one NewTool, one Run / Stream. No module registry, no presets, no second constructor.

/secure-default

Shell and HTTP refuse to exist without allowlists. Secrets never reach the model. Every redirect is re-validated.

/durable

A run can pause for a person, persist in the session, and resume in another process, including inside a sealed box.

/batteries

A2A, MCP, evals, OTel, triggers, memory, skills, graph and swarm, as small packages rather than a platform.

Start with one file.

The quickstart runs offline with a mock model. Add a real provider when you are ready; the rest of the code does not change.

Versioning

kritrim follows semantic versioning. Within v1 nothing exported is removed or changed, interfaces you implement gain no methods, and stored sessions, audit logs and traces stay readable; docs/API.md spells out the promise and CI checks it. Quickstart

From an empty folder to an agent with a typed tool, a stream and a saved conversation.

Hello

package main

import (
	"context"
	"fmt"
	"log"

	"github.com/ganeshdipdumbare/kritrim"
)

func main() {
	a, err := kritrim.New(kritrim.Config{
		Model:        kritrim.Anthropic("claude-sonnet-5-5"),
		Instructions: "You are concise.",
	})
	if err != nil {
		log.Fatal(err)
	}
	defer a.Close()

	res, err := a.Run(context.Background(), "Say hello in five words.")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(res.Text)
}

No key? Use kritrim.Mock(kritrim.Turn{Text: "hello"}) and the same code runs offline.

A typed tool

func weather(ctx context.Context, in struct {
	City string `json:"city" desc:"city name"`
}) (string, error) {
	return "18C and light rain in " + in.City, nil
}

a, _ := kritrim.New(kritrim.Config{
	Model: kritrim.Mock(
		kritrim.TurnTool("weather", map[string]any{"city": "Lisbon"}),
		kritrim.Turn{Text: "It is raining in Lisbon."},
	),
	Tools: []kritrim.Tool{kritrim.NewTool("weather", "Get the weather", weather)},
})
defer a.Close()

res, _ := a.Run(ctx, "What is the weather in Lisbon?")

The schema comes from the Go type. A string result goes to the model as is; anything else is JSON.

Offline first

Every example in the repository compiles and runs against the mock model, so the docs cannot drift from the API.

Concepts

The words used across these docs, in one place.

TermWhat it is
AgentWhat kritrim.New(Config) returns: a model, tools, hooks, a session store and optional sandbox.
RunOne Run or Stream call. It ends with a Result: text, steps, usage, stop reason and interrupts.
StepOne model call inside a run, plus the tool calls it asked for.
ToolA typed Go function with a name, a derived JSON Schema and a result.
SessionA conversation stored under an id (Thread("id")), including paused approvals. Memory, file or SQL.
HookA callback around the run, a model call or a tool call. Hooks can observe and shape; built-in security runs first.
ApprovalA risky tool asks Config.Approve. The decision can be synchronous or a durable pause.
InterruptA paused approval with a stable id. Resume with Decisions.
SandboxWhere shell and file tools run: Docker, Local (development) or SSH.
SealedThe whole agent runs in a sandbox. The host only brokers model calls, secrets, tools, audit and approvals.
BrokerThe one path built-in tools use for network, processes and files. It enforces allowlists, SSRF checks and redaction.

Reasoning

One setting, five providers. Effort becomes Anthropic extended thinking, OpenAI reasoning_effort, Responses reasoning.effort, Gemini thinkingConfig and Bedrock reasoning_config.

a, _ := kritrim.New(kritrim.Config{
	Model:     kritrim.Anthropic("claude-sonnet-5-5"),
	Reasoning: &kritrim.Reasoning{Effort: "high"}, // low | medium | high
})

Budget sets the thinking-token allowance exactly; the effort levels map to 1024, 4096 and 16384. Include: true streams the thinking back as reasoning events where the provider returns it.

Thinking tokens are output tokens

They count against MaxOutputTokens and the run's budget. A budget that cannot hold the thinking allowance is refused before the call, rather than capped into a provider error. Anthropic requires its thinking blocks to come back with their signature before it will accept a tool result, so kritrim keeps them on the assistant message and replays them.

Guardrails

A provider guardrail screens what goes in and what comes out. For Bedrock it runs inside the Converse call; for any model, guard.Bedrock applies the same guardrail with ApplyGuardrail and fails closed.

model := kritrim.Bedrock("anthropic.claude-sonnet-5-5", kritrim.ModelConfig{
	Guardrail: &kritrim.Guardrail{ID: "gr-123", Version: "1"},
})

// Any provider: prompts, replies and (with Tools) tool results.
hooks, _ := guard.Bedrock(guard.BedrockConfig{ID: "gr-123", Version: "1", Tools: true})

Other providers refuse ModelConfig.Guardrail at New instead of ignoring it. When any provider's safety system blocks a reply (Bedrock guardrail_intervened, OpenAI content_filter, Anthropic refusal, Gemini SAFETY), the run ends with kritrim.StopGuardrail and that reply's tool calls do not run.

Routing and fallback

Route decides up front, per run. Fallback reacts to a failure. They compose — fallbacks apply to whatever Route chose, and the audit log records the model the run actually used.

a, _ := kritrim.New(kritrim.Config{
	Model: small,
	Route: func(ctx context.Context, prompt string) kritrim.Model {
		if len(prompt) > 500 {
			return large
		}
		return nil // nil means Config.Model
	},
	Fallback: []kritrim.Model{kritrim.OpenAI("gpt-4.1")},
	Retry:    &kritrim.Retry{Max: 3},
})

Tools

The schema is derived from the Go type; the callable is not exported, so NewTool is the only way to define one.

type SearchIn struct {
	Query string `json:"query" desc:"what to look for"`
	Limit int    `json:"limit,omitempty" desc:"max results"`
	Sort  string `json:"sort,omitempty" enum:"relevance,date"`
}

search := kritrim.NewTool("search_tickets", "Search support tickets",
	func(ctx context.Context, in SearchIn) ([]Ticket, error) {
		return db.Search(ctx, in.Query, in.Limit)
	})

a, _ := kritrim.New(kritrim.Config{Model: model, Tools: []kritrim.Tool{search}})
  • Tags: json, desc and enum. omitempty or a pointer makes a field optional.
  • Results: a string goes to the model as is; anything else is JSON.
  • Errors: a returned error becomes an error tool result, so the model can recover.
  • Risky: kritrim.Risky(tool) asks Config.Approve before the call.
  • Validated: the model's arguments are checked against the schema before the tool runs, for typed, raw and MCP tools alike: types, required fields, enum/const, unknown fields, string length and pattern, numeric ranges, array sizes, anyOf/oneOf/allOf/not and local $ref. A schema keyword that cannot be enforced (a remote $ref, if/then, patternProperties…) makes the call fail instead of passing unchecked.

Parallel calls

One model step can ask for several tools. ToolConcurrency runs them together; risky tools always stay sequential so approvals keep their order.

a, _ := kritrim.New(kritrim.Config{
	Model:           model,
	Tools:           tools,
	ToolConcurrency: 4,
})

Direct calls

out, err := a.CallTool(ctx, "search_tickets", map[string]any{"query": "refund"})

Dynamic schemas

MCP servers and simulators need a schema they did not get from a Go struct:

t := kritrim.NewRawTool("lookup", "Look up a record", schema,

Web fetch

WebFetch is HTTP for reading: one GET, and HTML turned into readable text instead of markup. A page of HTML is mostly tags, scripts and navigation, and sending that raw spends the context window on nothing. Use HTTP when the model needs methods, headers and the exact response; use WebFetch when it needs to read something. A page that builds its content in the browser comes back nearly empty — there is no DOM and no JavaScript.

A page is data, not instructions

Fetched text reaches the model as a tool result. A page that says "ignore your instructions" is a page saying so, not a user asking. Keep the allowlist as narrow as the task.

Todos

A long task drifts: the model finishes step two, forgets steps four and five, and declares victory. Todos keeps the plan in session state, so it survives a pause, a resume and a restart along with the conversation, and it refuses a list with two items in progress. Put "keep the todo list current" in Instructions; the tool stores a plan, it does not enforce one.

Python

a, _ := kritrim.New(kritrim.Config{
	Model:   model,
	Tools:   []kritrim.Tool{kritrim.Python(kritrim.PythonConfig{})},
	Sandbox: kritrim.Docker(kritrim.DockerConfig{Image: "python:3.13-slim"}),
	Approve: approve,
})

This is the one built-in tool whose argument cannot be checked: an allowlist constrains a command, and Python is a language. It is risky, it requires Config.Sandbox (or sealed mode), and it refuses to run on the host unless you set AllowUnsafeHost. The code reaches the interpreter on stdin, so there is no shell and nothing to quote.

Stream returns an iter.Seq2. Breaking out early cancels the run and cleans up.

	if err != nil { break }
	if e.Type == kritrim.EventText { fmt.Print(e.Text) }
}

Sessions and state

A session is a conversation plus a small key-value state. It is version-checked, so two writers cannot silently overwrite each other.

a, _ := kritrim.New(kritrim.Config{
	Model:   model,
	Session: kritrim.FileSessions(".agent/sessions"),
	// or kritrim.MemorySessions(), kritrim.SQLSessions(db, cfg)
})
defer a.Close()

a.Run(ctx, "My name is Ada.", kritrim.Thread("user-42"))
res, _ := a.Run(ctx, "What is my name?", kritrim.Thread("user-42"))

State

Tools and hooks read and write per-session state. It is saved with the session and never sent to the model.

kritrim.StateFrom(ctx).Set("seen", true)
v := kritrim.StateFrom(ctx).Get("seen")

Fork, cancel, idempotency

a.Fork(ctx, "user-42", "user-42-experiment") // snapshot, including paused state
a.Cancel("run-7")                            // stop a run started with kritrim.RunID("run-7")
res, _ := a.Run(ctx, "charge", kritrim.Idempotency("order-1234"))
Conflict

If another process saved the session first, Save returns ErrSessionConflict. Reload and retry; the run never silently loses a turn.

Signed history

Message history is an instruction channel. An agent replays whatever the store returns and acts on it, so write access to a shared Redis, a database with a wide grant or a mounted volume is write access to the user's instructions. SignedSessions makes the store hold data the agent verifies instead of data it trusts.

key := loadKeyFromKMS() // 32+ random bytes, kept out of the store it protects
a, _ := kritrim.New(kritrim.Config{
	Model:   model,
	Session: kritrim.SignedSessions(kritrim.FileSessions(".agent/sessions"), key),
})

_, err := a.Run(ctx, "continue", kritrim.Thread("user-42"))
if errors.Is(err, kritrim.ErrSessionTampered) {
	// someone edited the stored conversation; nothing was replayed
}

Every save is HMAC-SHA256 over the thread id, the messages, the state and any pending approval. A load that does not match is refused, and so is a record with no signature at all: whoever can edit the record can also delete its signature.

Content, not freshness

The signature catches an edit. It does not catch a deleted session or a rollback to an older signed copy. To migrate a store with unsigned sessions, read each through the plain store and save it once through the signed one.

Context management

Keep a long conversation inside a token budget without losing anything on disk.

a, _ := kritrim.New(kritrim.Config{
	Model:   model,
	Session: kritrim.FileSessions(".agent/sessions"),
	Context: &kritrim.ContextConfig{
		MaxTokens: 60_000,
		KeepLast:  30,
		Strategy:  kritrim.SummarizeWith(small, ""), // or KeepWindow(), Summarize(fn)
	},
})

With no ContextConfig the whole history is sent on every step, and a long thread eventually hits the provider's own limit. With one, nothing happens while the history fits. Once it goes over MaxTokens, the strategy decides what the call sends.

Strategies

StrategyWhat it sendsCost
KeepWindow() (default)the system prompt and the last KeepLast messagesno model call
SummarizeWith(model, instructions)a summary of what was dropped, then the recent messagesone call to model, usually a small one
Summarize(fn)whatever your function returns in place of the dropped messagesyours

Use KeepWindow when old turns stop mattering, like a support chat. Use SummarizeWith when an early decision still matters thirty turns later. KeepLast defaults to 20.

Your own strategy

type Strategy interface {
	Compact(ctx context.Context, msgs []Message, cfg ContextConfig) ([]Message, error)
}

Compact gets the full history and returns the messages to send. It must return a valid conversation: a tool result cannot come first, and every tool result it keeps needs the assistant turn that asked for it. The built-in strategies never orphan a tool result.

Estimating tokens

n := kritrim.EstimateTokens(msgs)

This is the same estimate the run's token budget uses: about four characters per token plus a small per-message overhead. It needs no network call and no tokenizer, is within about 10% for English prose, and under-counts dense JSON, so leave headroom.

The session keeps everything

A strategy only changes what is sent to the model. The stored session always has the full history, so compaction is reversible: change the strategy and the next run sees the old turns again.

Approvals

Synchronous for a CLI; durable for a server that answers hours later.

In-process

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Tools: []kritrim.Tool{kritrim.Risky(refund)},
	Approve: func(ctx context.Context, req kritrim.Approval) (kritrim.Decision, error) {
		fmt.Println(req.Message)
		return kritrim.Approve(), nil // or Reject, Edit, Respond
	},
})

Durable pause

Return Pause(). The run saves the pending step with the session and returns interrupts.

Approve: func(ctx context.Context, req kritrim.Approval) (kritrim.Decision, error) {
	return kritrim.Pause(), nil
},

res, _ := a.Run(ctx, "Refund A-17", kritrim.Thread("ticket-981"))
// res.Stop == "interrupt"; res.Interrupts[0].ID

// Later, in another process with the same session store:
res, _ = a.Run(ctx, "", kritrim.Thread("ticket-981"),
	kritrim.Decisions(map[string]kritrim.Decision{
		res.Interrupts[0].ID: kritrim.Approve(),
	}))
  • The model is not called again on resume; only the remaining tools run.
  • A second resume gets ErrSessionConflict, so a tool runs once.
  • A paused thread refuses a new prompt until the interrupts are answered.
  • This works in sealed mode: pending state crosses the RPC boundary and survives a box restart.

Structured output

Ask for a Go type instead of text. One repair round, then ErrOutput.

type Trip struct {
	City    string   `json:"city"`
	Packing []string `json:"packing" desc:"things to pack"`
	Budget  int      `json:"budget_eur,omitempty"`
}

var trip Trip
_, err := a.Run(ctx, "Plan Lisbon", kritrim.Output(&trip))
if err != nil { /* kritrim.ErrOutput */ }
fmt.Println(trip.City, trip.Packing)

OpenAI and Gemini use native JSON schema; Anthropic and Bedrock get a forced tool; OpenAI-compatible providers can use JSON mode. The schema is derived from the same tags as a tool.

Security

Enabling a built-in capability is the grant. There is no second policy file to drift from the code.

Default deny

HTTP and Shell refuse to be constructed without an allowlist. Files is read-only unless Write: true.

SSRF and rebinding

Exact allowlisted hosts may be private; wildcard hosts must be public, checked at dial time on the IP actually connected to, so DNS rebinding cannot reach an internal address. Every redirect is re-validated.

Secrets

secret://NAME resolves at use and is redacted from output, events and audit. A request that carries a secret never follows a redirect to another host. Sealed boxes get random placeholders only.

No inherited credentials

Shell commands, MCP stdio servers and local boxes start with a minimal environment (PATH, HOME, locale, temp dir). Your API keys never reach them; pass extras with ShellConfig.Env or MCPConfig.Env.

Symlink-safe files

File tools open their root with os.Root: a symlink inside the root cannot read or write outside it.

Validated arguments

Tool arguments are checked against the tool schema before the call, so a model cannot pass types, values or fields the tool did not declare.

Guardrails

A Bedrock guardrail can screen every call, inside Converse or for any model with guard.Bedrock. A blocked reply ends the run with StopGuardrail and its tool calls never run.

Audit

One hash-chained JSON line per model, tool and approval. With AuditKey the chain is HMAC-signed and a signed head detects truncation.

Limits

a, _ := kritrim.New(kritrim.Config{
	Model:  model,
	Limits: kritrim.Limits{Steps: 20, ToolCalls: 50, Tokens: 200_000},
	Audit:  kritrim.AuditFile(".agent/audit.jsonl", kritrim.AuditKey(auditKey)),
	Secrets: map[string]string{"GITHUB_TOKEN": os.Getenv("GITHUB_TOKEN")},
})

Defaults: 20 steps, 100 tool calls and kritrim.DefaultTokenLimit (1,000,000) tokens per run. Set Tokens: -1 to remove the token cap. The token budget is checked before every model call, including the structured-output repair call: a call whose estimated input does not fit is refused, and the output limit is capped to what remains. In sealed mode the host enforces the run's Limits.Tokens as well as Sealed.MaxTokens.

Redaction and policy

deny, _ := guard.Deny(`(?i)ignore all previous`, "prompt injection")
a, _ := kritrim.New(kritrim.Config{
	Model: model,
	// Guards first, so tracing sees redacted values.
	Hooks: kritrim.Chain(deny, guard.PII("email", "credit_card"), trace.OTel(otelCfg)),
})

kritrim.Chain combines any number of hook sets. They run in the order given; a Before hook that errors or denies stops the chain.

Hooks that steer

A hook can ask for another answer, reroute a tool call, or end the run, without forking the loop:

Hooks: kritrim.Hooks{
	AfterModel: func(ctx context.Context, e *kritrim.ModelEvent) {
		if strings.Contains(e.Response.Text, "TODO") { e.Retry = true } // capped by Retry.Max
	},
	BeforeTool: func(ctx context.Context, e *kritrim.ToolEvent) error {
		if e.Call.Name == "web_search" { e.Swap = "internal_search" }
		return nil
	},
	AfterTool: func(ctx context.Context, e *kritrim.ToolEvent) {
		if e.Result.IsError { e.End = "tool failed" } // Result.Stop == StopHook
	},
}

A swapped call goes through approval, argument validation and BeforeTool again, so a swap cannot skip a check, and it cannot swap a second time.

Trust boundary

The broker governs built-in tools. Your own Go tools are code you compiled into the binary. Put untrusted work in a sandbox.

Authorization

Config.Tools answers "may this agent refund". Policy answers "may this caller refund this much".

import "github.com/ganeshdipdumbare/kritrim/authz"

policy, err := authz.New(
	authz.Permit("*").For("admin"),
	authz.Permit("current_time", "web_*"),
	authz.Permit("refund").For("support").
		When(func(r authz.Request) bool { return r.Number("amount") <= 100 }).
		Because("support may refund up to 100 euros; ask a manager for more"),
	authz.Forbid("shell"),
)
if err != nil { log.Fatal(err) }

a, _ := kritrim.New(kritrim.Config{Model: model, Tools: tools, Hooks: policy.Hooks()})
a.Run(ctx, "refund order A-17", kritrim.User("u-7"), kritrim.Roles("support"))

Three rules

The semantics are Cedar's:

  1. An explicit Forbid beats every Permit.
  2. Otherwise, one matching Permit is enough.
  3. With nothing matching, the call is denied.

Default deny is the point. Adding a tool to an agent does not quietly widen what every caller can reach, and a typo in a policy fails closed.

Building a policy

PieceNarrows the policy to
Permit(tools...), Forbid(tools...)these tool names; * and web_* match with path.Match
.For(roles...)callers with one of these roles
.By(users...)these user ids
.When(fn)calls the condition accepts; read arguments with r.Number, r.Text, r.HasRole
.Because(text)sets what the model is told when this policy denies

Identity comes from the run, through kritrim.User and kritrim.Roles (or Config.User and Config.Roles), so one agent serves many callers. Conditions see the arguments the model chose, after any approval edited them, which is where ceilings and path prefixes belong. A condition that panics denies the call instead of crashing the run.

A denial is a message, not an error

The run keeps going. The model is told the call was blocked and why, and usually explains the limit to the user. Write Because for the model to read: it is the sentence the user ends up hearing. A call that nothing permitted is told the Because text of every policy covering that tool, so a caller who went over a ceiling learns what the ceiling was.

To check a decision outside a run, for a UI that greys out a button, call policy.Check(authz.Request{User: "u-7", Roles: roles, Tool: "refund", Args: args}); it returns nil when allowed and an error wrapping authz.ErrDenied when not.

Policy can only narrow

Policy runs after kritrim's own checks. It cannot grant Shell a command its allowlist lacks, and it cannot waive an approval. Put policy.Hooks() first in kritrim.Chain so a denied call never reaches tracing or other hooks as if it ran.

What crosses the boundary

The box needsThe host does
a model callchecks the token budget before the call, injects the key, calls the provider one call at a time, streams tokens back
a secret://returns a random placeholder, substitutes it only for allowed hosts, never follows a cross-host redirect with it, and redacts responses
a bridged toolruns it on the host; a risky one runs only for a call the host approved, once, with exactly the approved arguments

an approvalasks Config.Approve on the host with a host-written message and persists the pause
an audit entrywrites it marked source: "box" with the host's identity

The box is treated as untrusted. User, roles, thread and run id come from the run the host started, never from the box. Every host capability call holds a lease on that run: when the run ends, in-flight calls are canceled and waited for, and new ones are refused.

Local is not isolation

kritrim.Local() exists for development and requires AllowUnsafeLocal: true. Use Docker or a cloud sandbox for a real boundary.

MCP

Connect stdio and Streamable HTTP servers. Tools are namespaced and go through the same broker and approval rules.

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	MCP: []kritrim.MCPConfig{
		{Name: "github", Command: "npx", Args: []string{"-y", "@modelcontextprotocol/server-github"}},
		{Name: "docs", URL: "https://mcp.example.com/mcp",
			Headers: map[string]string{"Authorization": "Bearer secret://MCP_TOKEN"}},
	},
})
  • Tools are named server__tool.
  • Each server has a timeout, an HTTP host allowlist and an optional Risky flag.
  • stdio servers do not inherit your environment; pass what they need in Env. HTTP servers never get a redirect off their host.
  • In sealed mode the host connects and bridges the tools into the box automatically.

A2A

Serve an agent over the Agent-to-Agent protocol and call remote agents with the same result type.

Server

srv, _ := a2a.NewServer(a2a.ServerConfig{
	Card:  a2a.Card{Name: "Triage", Description: "Routes support tickets"},
	Auth:  a2a.Bearer(os.Getenv("A2A_TOKEN")),
	Agent: func(contextID string) (*kritrim.Agent, error) { return buildAgent(contextID), nil },
	Tasks: a2a.MemoryTasks(), // or a2a.SQLTasks(db, cfg)
	PushAllowPrivate: false,
})
http.ListenAndServe(":9000", srv)

Client

c, _ := a2a.NewClient(a2a.ClientConfig{
	Endpoint: "https://triage.internal",
	Headers:  map[string]string{"Authorization": "Bearer secret://A2A_TOKEN"},
	// OAuth client credentials:
	TokenURL: "https://auth.example.com/token", ClientID: "id", ClientSecret: "secret",
	// Push every task to a webhook:
	PushURL: "https://app.example.com/a2a/events", PushToken: "shared",
})
res, _ := c.Run(ctx, "ticket 42")
tool := c.AsTool("triage", "Routes a ticket")

// Files: images reach the model, text files are inlined.
res, _ = c.Run(ctx, "summarize", a2a.Files(a2a.File{Name: "notes.md", MimeType: "text/markdown", Bytes: notes}))

// A remote agent as a graph node.
g, _ := multiagent.Sequence(multiagent.Step{Name: "triage", Node: c.Node()})

What is implemented

  • Agent card, message/send, message/stream, tasks/get, tasks/cancel.
  • Per-context agents with an LRU, text, data and file parts, and interrupt → input-required → resume.
  • File parts: images go to the model, text files are inlined in the prompt, other types are refused. A file URI is fetched only from a host in ServerConfig.FileHosts, checked at dial time, without redirects, within MaxFileBytes.
  • Push notifications with a token, and tasks/pushNotificationConfig/{set,get,list,delete}. Push URLs must be public http(s) (checked at set time and at dial time), redirects are not followed, and header values are sent as given: secret:// is never resolved on the server.
  • Bearer auth (constant-time; an empty token is refused) and OAuth client credentials.
  • Per-caller isolation: with a2a.Tokens(map[token]principal) (or any Auth that implements Principal), each task, context, conversation and push config belongs to the caller that created it. Other callers get "task not found". With a single Bearer token, all callers share one principal.
  • The client only follows redirects on the same allowed host, so its credentials stay where you sent them.

Triggers

Run an agent on a schedule or from a signed webhook.

sched, _ := trigger.NewScheduler(agent,
	trigger.Schedule{Name: "digest", Cron: "0 9 * * mon-fri", Location: berlin, Thread: "daily", Prompt: "summarize yesterday"},
	trigger.Schedule{Name: "poll", Every: 10 * time.Minute, Thread: "poll", Prompt: "check the queue"})
sched.SetStore(store) // shared by every instance: each tick runs once
sched.Start(ctx)
defer sched.Close()

hook, _ := trigger.Webhook(trigger.WebhookConfig{
	Agent:  agent,
	Secret: "secret://HOOK_SECRET",
})
http.Handle("/hook", hook)

// Sender side:
ts := time.Now()
req.Header.Set(trigger.TimestampHeader, strconv.FormatInt(ts.Unix(), 10))
req.Header.Set(trigger.IdempotencyHeader, "evt-123")
req.Header.Set(trigger.SignatureHeader, trigger.Sign(secret, ts, "evt-123", body))

The HMAC-SHA256 signature covers a versioned, length-prefixed encoding of the timestamp, the idempotency key and the body. Requests outside Tolerance (default 5 minutes) are refused, so a captured request cannot be replayed later or under a new key. Each delivery runs once: duplicates, including concurrent ones, get the first result, and a delivery without a key is identified by its signature. Reusing a key for a different body returns 409. Deliveries are remembered for DedupeTTL in a DedupeStore: trigger.MemoryDedupe(n) for one process (when full of unexpired deliveries it answers 503 with Retry-After rather than forgetting any), or trigger.SQLDedupe(db, cfg) on Postgres, SQLite or MySQL when several instances serve the webhook. Errors are logged, not returned.

Schedules take a five-field cron expression or a descriptor such as @daily, read in Location, or an Every interval aligned to the epoch so instances agree on when a tick is due. Names (default: the thread) must be unique. A schedule skips a tick when its previous run is still going.

The CLI

kritrim-evals runs a suite without Go glue code. run starts your agent program once per case with the input on stdin; the program prints the answer, or a kritrim.Result as JSON to keep tool calls for trajectory checks.

Built-in criteria

Writing a good rubric is most of the work of an LLM judge. evals.Judge takes one of twelve ready-made ones:

Evaluators: []evals.Evaluator{
	evals.Judge(evals.Faithful, judge), // every claim backed by a tool result
	evals.Judge(evals.Achieved, judge), // the task was done, not just described
	evals.Judge(evals.Harmless, judge),
}

1.0 is always good, including for the safety criteria, so a report never needs a "lower is better" footnote. Judges see the trajectory, not only the final answer, so Faithful can check claims against what the tools actually returned.

A trajectory check confirms a tool was called; ToolParameters checks how:

evals.ToolParameters("refund", func(args map[string]any) error {
	if args["amount"].(float64) > 100 {
		return errors.New("refund over the ceiling")
	}
	return nil
})

Chaos testing

A suite run on a good day only proves the agent works on a good day. Chaos makes tools fail on purpose, so you see what the agent does when the world does not cooperate: report success anyway, retry the same call until the step limit, or find another way.

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Tools: tools,
	Hooks: evals.Chaos(evals.ChaosConfig{
		Fail:    map[string]int{"http_request": 1}, // first call per run fails; "*" for every tool
		Latency: 2 * time.Second,
	}),
})
report, _ := evals.Experiment{
	Cases:      cases,
	Evaluators: []evals.Evaluator{evals.Resilient(), evals.Judge(evals.Recovered, judge)},
}.Run(ctx, run)

The failures are counted, not random: the same case fails the same call every time, so a red result is reproducible and a fix is provable. Resilient is the deterministic half (the run finished despite a failure); Judge(Recovered, …) asks whether what the agent did instead made sense. A run where nothing failed passes Resilient with a reason saying so; check FailedTools(result) when you need proof the failure actually happened. Latency delays every tool call, to find runs that only work because a tool was fast. Counting is per run id, so give concurrent runs a kritrim.RunID or a thread.

Goal loop

One Run ends when the model stops calling tools. That is the model's judgement that it is finished, not a fact. plugin.GoalLoop closes the gap by re-prompting the same thread until a check you write says the job is done.

res, err := plugin.GoalLoop(ctx, agent, plugin.GoalConfig{
	Goal:   "go build ./... exits zero",
	Thread: "fix-build",
	Done: func(ctx context.Context, res *kritrim.Result) (bool, error) {
		return exec.Command("go", "build", "./...").Run() == nil, nil
	},
	MaxAttempts: 5, // the default
})
if errors.Is(err, plugin.ErrGoalNotMet) {
	// res is the last attempt; show it to a human
}
  • Check the world, not the transcript. A model that says the tests pass has only said so. Run the tests in Done.
  • Write the goal as a test. "every file under ./api compiles" is checkable; "fix the API" is not. Every retry prompt restates it.
  • Thread is required. Attempts share one conversation, so the agent remembers what it already tried instead of repeating its first move.
  • Approvals stop the loop. A run that pauses for an approval comes back as it is. Resume with kritrim.Decisions, then call GoalLoop again.

Nudge customises the retry prompt. plugin.Goal(goal) keeps the goal in the system prompt when you drive the loop yourself.

Observability

Audit is built in. Traces, metrics and logs are one hook away.

Audit

a, _ := kritrim.New(kritrim.Config{
	Model: model,
	Audit: kritrim.AuditFile(".agent/audit.jsonl", kritrim.AuditKey(key)),
})
// later
if err := kritrim.VerifyAudit(".agent/audit.jsonl", kritrim.AuditKey(key)); err != nil { ... }

With AuditKey (32+ random bytes from a KMS or secret store, not on the log's host) every entry is chained with HMAC-SHA256 and audit.jsonl.head holds a signed record of the last entry. Someone who can write the file but lacks the key cannot rewrite or truncate it without VerifyAudit failing. Without a key the plain SHA-256 chain only detects accidental corruption. Ship the head to external storage to detect a rollback of both files.

Before its first append, a sink verifies the existing log with its own key and refuses to extend a log that fails: one that was truncated, written unkeyed or with another key, or that lost its head. An empty key is an error, never "no signing". After a failed write the sink re-reads and re-verifies the file before the next one.
